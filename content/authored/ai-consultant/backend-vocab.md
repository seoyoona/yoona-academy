백엔드 개발자와 회의하다 보면 "환경변수 세팅해 주시고, 웹훅은 이 URL로, 파일은 S3에 올릴 거라서, 에러는 로그로 쌓을게요"처럼 단어가 쏟아진다. 이 단어들이 모두 **구체적인 부품**이지 개발자의 입버릇이 아니다. 각각 빠지면 서비스가 멈추거나, 디버깅이 불가능해지거나, 사고가 난다. 이 레슨은 PM이 반드시 가져야 할 백엔드 단어장 — 환경변수·웹훅·파일업로드·에러로그, 그리고 그 뒤에 있는 큐·캐시까지 — 를 한 번에 정리한다.

## 환경변수(env) — 서비스의 '설정 다이얼'

**환경변수**는 코드 밖에 두는 설정값이다. DB 주소·비밀번호·API 키·JWT 시크릿 같은 값들을 코드에 직접 쓰지 않고 `.env` 파일이나 클라우드 설정에 넣어둔다.

왜 굳이 코드 밖으로 빼는가:

1. **보안**: 비밀값이 코드/Git에 올라가면 유출 = 사고.
2. **환경 분리**: 개발(local)·검증(staging)·실서버(production)에서 **같은 코드**를 쓰되 **다른 값**(다른 DB, 다른 API 키)을 쓰려면.
3. **변경 용이**: 값이 바뀌어도 코드를 고칠 필요 없이 설정만 바꾼다.

PM이 꼭 알아야 할 것: **"로컬에선 되는데 실서버에선 안 된다"는 십중팔구 환경변수 문제**다. 실서버 환경변수가 빠졌거나 달라서. 그래서 환경변수 목록을 산출물로 관리하는 게 중요하다. (대표 항목은 이전 Git·Auth 레슨에 정리했고, Phase 5 클라우드에서 다시 다룬다.)

| 변수 예 | 의미 |
|---|---|
| `DATABASE_URL` | DB 접속 주소(계정/비번/호스트 포함) |
| `JWT_SECRET` | 로그인 토큰 서명용 비밀값 |
| `STRIPE_SECRET_KEY` | 결제사 비밀 키 |
| `AWS_REGION` | 클라우드 지역(예: 서울 `ap-northeast-2`) |
| `NEXT_PUBLIC_API_URL` | 프론트가 쓸 API 주소(클라이언트에 노출돼도 되는 값) |

`NEXT_PUBLIC_`처럼 접두어가 붙은 값만 클라이언트에 노출된다. **비밀값은 절대 `PUBLIC`으로 붙이지 않는다**는 규칙을 팀에 달아두자.

## 웹훅(webhook) — 남이 우리를 '때려주는' 전화

**웹훅**은 외부 서비스가 **우리 서버로 알림을 밀어 넣는(reverse) HTTP 요청**이다. 보통은 우리가 남에게 요청하지만, 웹훅은 반대로 남이 우리에게 온다.

- 결제 완료 → 결제사(토스·Stripe)가 우리 `/webhooks/payment`로 "결제 x원 완료됨" POST.
- GitHub에 푸시 → GitHub이 우리 서버로 "코드 올라옴" 알림.
- 카카오톡 전송 결과 → 알림 서비스가 우리에게 "전송 성공/실패" 회신.

왜 필요한가. 우리가 결제사에 "결제 끝났어?"고 1초마다 물어보는(polling) 건 비싸고 느리다. 대신 결제사가 "끝나면 너한테 알려줄게"라고 약속하고, 우리는 받는 편에 대기하는 게 효율적이다.

**주의점**: 웹훅은 **신뢰할 수 있게 처리**해야 한다. 같은 알림이 두 번 올 수도(중복), 올 때 순서가 바뀔 수도 있다. 그래서 (1) **idempotent**(같은 알림이 두 번 와도 한 번 처리)하게 만들고, (2) **서명 검증**(이 요청이 진짜 결제사가 보낸 건지)을 한다. 결제 웹훅을 그냥 믿고 처리하면 "돈만 내고 알림이 안 와서 두 번 결제됨" 사고가 난다.

## 파일 업로드/저장소 — 파일은 DB에 안 넣는다

사용자가 사진·문서를 올리면, 이 **파일은 DB에 넣지 않고 전용 저장소에** 둔다. (DB에 넣으면 DB가 비대해지고 느려진다.)

- **저장소**: AWS S3, Supabase Storage, Cloudflare R2 같은 '파일 창고'.
- **흐름**: 사용자 업로드 → 저장소에 파일 저장 → DB에는 **파일의 주소(URL)** 만 저장 → 화면은 그 URL로 이미지를 띄움.

PM이 "프로필 사진 업로드"를 기획하면, 이게 (1) 프론트(올리는 화면) (2) 저장소(파일 창고) (3) DB(URL만) — 세 군데에 걸친 작업임을 알아야 한다. 그리고 "파일은 5MB 제한, 이미지만" 같은 **제한**이 필수(무제한이면 저장소 비용 폭발 + 보안 위험). 업로드 시 파일 종류·크기 검증(클라이언트 + 서버 이중, 이전 레슨)을 잊지 말자.

## 에러 로그 — "안 된다"를 해부하는 도구

**로그**는 서버가 자기 한 일을 기록해 둔 글이다. 정상 요청도, 에러도 시간 순으로 남긴다. "어제 결제 안 됐다는 문의 3건"이 왔을 때, 로그가 없으면 원인을 못 찾는다. 로그가 있으면 "그 시간에 결제사 응답이 5초로 timeout 났다"까지 추적된다.

최소한 갖춰야 할 것:

- **에러 로그**: 실패한 요청의 원인(스택트레이스).
- **접근 로그**: 누가 언제 어느 API를 쳤는지.
- **모니터링/알림**: 에러가 임계치를 넘으면 슬랙/이메일로 알림(CloudWatch, Sentry 등).

PM 상담 팁: **"장애 났을 때 로그가 있나요?"**를 기본 질문으로. 로그가 없는 서비스는 "재현해야 원인을 안다"는 뜻이고, 재현 안 되는 버그는 못 고친다.

## 큐와 캐시 — 들으면 아는 척 말고 질문할 것

심화 단어 두 개:

- **큐(queue)**: 오래 걸리는 일(이메일 대량 발송, 엑셀 파싱)을 '줄'에 넣고 나중에 처리. "즉시 안 되고, 잠시 뒤 처리됩니다"라는 UX가 필요.
- **캐시(cache)**: 자주 쓰는 결과를 임시로 저장해 빠르게. "DB까지 안 가고 메모리에서 바로 줄게요".

이들은 초기엔 없어도 되고, 트래픽이 커지면 들어간다. PM은 "지금 필요한가, 나중에 붙일 건가"의 시점을 개발자와 맞추면 된다. 본질은 "성능과 비용의 트레이드오프"다.

## worked example: "엑셀 올리면 사용자 1천명에게 알림"을 단어장으로 쪼개기

고객 요구: "관리자가 엑셀 올리면 파싱해서, 조건 맞는 사용자 1천명에게 카톡 알림."

1. 엑셀 **파일 업로드** → 저장소(S3)에 보관, DB엔 URL·상태 저장.
2. 서버가 **큐**에 "이 엑셀 처리해라" 작업을 넣는다 (사용자는 즉시 "처리 중" 응답).
3. 워커가 큐에서 꺼내 엑셀 파싱 → 대상 사용자 1천명 조회.
4. 알림 서비스에 발송 요청 → 서비스가 **웹훅**으로 "1천건 중 997건 성공, 3건 실패" 회신.
5. 실패 건은 **에러 로그**에 남기고, 관리자에게 "3건 실패, 재발송 버튼" 표시.
6. 환경변수(`KAKAO_API_KEY`, `S3_BUCKET` 등)는 `.env`/클라우드 설정에서만.

이 단어들이 다 쓰인다. 각각 빠지면 — 큐 없이 즉시 처리면 브라우저가 타임아웃나고, 웹훅 신뢰 처리 없으면 중복 발송, 로그 없으면 실패 원인 불명. "간단한 알림 기능"이 사실 6개 부품의 묶음이다.

## 실 사례(익명화) — "로컬에선 되는데 실서버에선"의 진짜 원인

> 실제 프로젝트 사례를 익명화해 옮겼다.

한 프로젝트에선 환경변수(DB 주소·결제·푸시·AI 키 등)를 코드와 완전 분리해 뒀다. 그런데 실서버 장애가 한 번 났을 때, 원인은 코드가 아니라 **"실서버 환경변수 누락"**이었다 — 개발엔 있던 값이 실서버 세팅에 빠져 있어, 서버가 DB·외부 서비스에 연결을 못 했다.

교훈: "로컬에선 되는데 실서버에선 안 된다"의 십중팔구가 이 패턴이다. 그래서 환경변수 목록(세팅값 표)을 **산출물로 관리**하는 것이 필수였다 — 어떤 값이, 어느 환경에, 들어있어야 하는지를 한 장으로 두는 것. 상담에서 "환경변수 목록이 있나요?"를 묻는 것이 이 사례의 실무 교훈이다.

## 흔한 실패 모드와 처방

- **환경변수 목록이 없다.** 누가 빼먹으면 실서버 장애. 처방: 필요 환경변수 표를 산출물로 유지.
- **웹훅을 중복 처리 없이 믿는다.** 같은 결제가 두 번 처리. 처방: idempotency 키 + 서명 검증.
- **파일을 DB에 넣는다.** DB 비대·성능 저하. 처방: 파일은 저장소, DB엔 URL만.
- **로그가 없다.** 장애 원인 불명. 처방: 최소 에러+접근 로그, 알림까지.

## 상담에 바로 쓰는 한 줄

"간단한 기능"이라는 말이 나오면, 환경변수·파일저장·웹훅·로그 중 몇 개가 걸리는지 세어 보라. 셋 이상이면 절대 "간단"이 아니다.

## 개발자가 이 단어 말할 때 (빠른 사전)

- **env / `.env`** — 코드 밖 설정값 창고.
- **webhook** — 남이 우리에게 밀어넣는 알림 요청.
- **S3 / Storage / Blob** — 파일 창고.
- **idempotent** — 여러 번 와도 한 번 효과.
- **polling** — 우리가 주기적으로 물어보는 것(webhook의 반대).
- **로그/모니터링/알림** — "무슨 일이 일어났는지"의 기록과 경고.

## ✍️ 산출물 과제

본인 서비스의 한 기능에서, 이 단어장의 단어 다섯 개(env, webhook, 저장소, 큐, 로그) 중 "이 기능에 필요한 것"을 모두 고르고, 각각 "왜 필요한가"를 한 줄로 적어라. 필요 없는 것도 적으며 그 이유를 써라.
